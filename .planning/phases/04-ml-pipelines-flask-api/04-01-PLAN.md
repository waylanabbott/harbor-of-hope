**Step 1: Notebook 01 — Donor Churn Classifier (ML-01)**
Create `ml-pipelines/notebooks/01-donor-churn-classifier.ipynb` using nbformat programmatically. The notebook MUST follow the mandatory 7-section structure:

Section 1 — Problem Framing (markdown cell):
- Business problem: Identify at-risk donors before they lapse to enable targeted retention campaigns
- Approach: Predictive (binary classification)
- Success metric: F1 score (balances precision/recall for imbalanced churn data)
- Stakeholders: Fundraising team, case managers

Section 2 — Data Acquisition and Preparation (code cells):
- Load `supporters.csv` (60 rows) and `donations.csv` (420 rows) with `pd.read_csv('../../data/lighthouse_csv_v7/...')`
- Filter to monetary donations only (`donation_type == 'Monetary'`)
- Engineer RFM features per supporter_id:
  - recency: days since last donation (from max donation_date)
  - frequency: count of donations
  - monetary_total: sum of amounts
  - monetary_avg: mean of amounts
  - monetary_std: std of amounts (fillna 0)
  - tenure_days: days from first to reference date
- Merge supporter demographics: supporter_type, acquisition_channel, status, region
- Target: `churned = (recency > 90).astype(int)` — no donation in last 90 days
- Numeric features: recency, frequency, monetary_total, monetary_avg, monetary_std, tenure_days
- Categorical features: supporter_type, acquisition_channel, region
- Train/test split: 80/20, stratify=y, random_state=42

Section 3 — Exploration (code cells):
- Target distribution bar chart (churned vs retained)
- RFM distribution histograms
- Correlation heatmap of numeric features
- Box plots of monetary features by churn status
- Print class balance counts

Section 4 — Modeling (code cells):
- Create ColumnTransformer: StandardScaler for numeric, OneHotEncoder(drop='first', handle_unknown='ignore') for categorical
- Model progression (each wrapped in sklearn Pipeline with preprocessor):
  1. LogisticRegression(max_iter=1000, random_state=42) — baseline
  2. DecisionTreeClassifier(max_depth=3, random_state=42) — interpretable (limit depth for 60 rows)
  3. RandomForestClassifier(n_estimators=100, max_depth=3, random_state=42)
  4. GradientBoostingClassifier(n_estimators=100, max_depth=2, random_state=42)
- Cross-validate each with cv=5, scoring='f1', print mean +/- std
- Select best model by CV F1, fit on full training set

Section 5 — Evaluation (code cells):
- Classification report on test set (precision, recall, F1 for each class)
- Confusion matrix using ConfusionMatrixDisplay
- ROC-AUC score and ROC curve plot
- Model comparison table as DataFrame

Section 6 — Causal Analysis (markdown + code cells):
- Feature importance from best model (use .feature_importances_ for tree models or permutation_importance)
- Feature importance bar chart
- Markdown: Discuss correlation != causation, potential confounders (seasonal giving, economic conditions), actionable recommendations (target high-recency donors)

Section 7 — Deployment (code cells):
- `joblib.dump(best_pipeline, '../../ml-pipelines/models/donor_churn.pkl')`
- Document expected input features as a DataFrame example
- Show example prediction call: `model.predict(sample_df)` and `model.predict_proba(sample_df)`
- Print the exact feature names the model expects
